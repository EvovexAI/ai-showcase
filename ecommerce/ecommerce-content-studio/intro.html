01

项目定位

它是什么、不是什么，一句话说清边界。

这是一个单品电商内容工厂：从「全网洞察」开始（公开网页检索提炼痛点/卖点/创意方向，免费开箱可用），到按平台规格批量生成主图套装、SKU 套图、详情页竖图与三类视频，全程带违禁词初筛、报价确认（生成前弹窗确认才扣费）与成果管理。生图/生视频由 BOLI CLI 承载。

#全网洞察#主图套装#详情页#违禁词初筛#BOLI CLI

交付物

  • 痛点 / 卖点 / 创意方向洞察报告
  • 主图套装 + SKU 套图 + 详情页竖图
  • 三类平台规格视频
  • 违禁词初筛 + 报价确认单 + 成果管理

解决什么问题

左边是现状的痛，右边是用了之后的变。

之前洞察靠手动刷网页，卖点提炼全凭感觉
之后公开网页检索自动提炼痛点/卖点/创意方向
之前主图/详情页外包又贵又慢
之后按平台规格批量生成，本地管理随时改
之前AI 生图费用不透明，违禁词踩雷
之后报价确认后才扣费；违禁词初筛前置

06

日常怎么用

单开网页只是「手动挡」。接入 EvoFlow 后，同一个能力有四种发起方式，外加一条沉淀闭环。

工作台对话发起

在 EvoFlow 对话框直接 @员工 甩一条任务，员工调起本台技能，洞察报告与全套内容直接回进对话。

手机 IM 发起

员工接入飞书 / 钉钉 / 微信等渠道后，手机发消息即可发起——通勤路上顺手一发，生成一套素材就跑完了。

自动化定时发起

把「生成一套素材」挂成自动化任务：按计划自动执行，结果准时出现在对话和面板里。

EvoFlow 面板直看

本台 UI 以扩展面板嵌进 EvoFlow，不切窗口，对话和操作台同屏。

沉淀闭环：越用越聪明关键不在跑一次，而在产出落进知识库，反哺之后的每一次发起

发起对话 / IM / 自动化任一入口把任务丢给员工
执行员工调本台技能流水线跑完，产出洞察报告与全套内容
沉淀报告进知识库电商内容库（建议命名）自动归档、可检索
复用员工查库再生成下次同类任务先查历史产出，结论更准
复用的结论又变成下一次发起的输入 —— 知识库越厚，建议越准
EvoFlow 接入本项目尚未注册 EvoFlow 资产——用 evoflow-onboarding-kit 一键接入：注册扩展面板 → 同步知识库 → 雇佣员工，四个脚本一条龙（已在拆解台 / 博主分析器打样）。
07

小白怎么上手

不写代码，三步跑通第一条产出。

开始前确认（一次性准备）Node.js 18+；npm install 后 npm run dev；全网洞察零密钥开箱可用；主图/SKU/详情页/视频生成需安装并登录 BOLI CLI（npm i -g @boli-ai/cli，账号有积分）。
1

起前后端

一次安装，前端 5173 + API 8790 同时起。

# 在项目根目录执行 npm install npm run dev # ✓ web http://localhost:5173 · api http://localhost:8790
2

建项目 → 全网洞察

选平台和语言建项目，素材入库（多视角图），跑全网洞察出痛点/卖点/创意方向。

3

生图生视频，确认报价后交付

主图/SKU/详情页/视频按需生成（需 BOLI CLI），违禁词初筛通过、报价确认后执行，成果进 generated/ 归档。

常见问题

洞察免费吗？
免费——公开网页检索提炼，不依赖付费 API，开箱可用。
生图报错？
确认 BOLI CLI 已安装并登录、积分充足；生成前会弹报价确认，取消不扣费。
能直接上架吗？
产出为素材与初筛，上架前请人工复核平台合规要求。

想自己做一个？0→1 提示词

把下面整段喂给 AI 编程助手（ZCode / Cursor 等）。蓝色填空是你要替换的部分。

从 0 到 1 建项目提示词替换蓝色填空 → 整段复制 → 发给 AI
# ── 角色与目标 ── 你是资深全栈工程师。请帮我从零开发一个本地工具：【电商智能创作中枢——全网洞察 + 主图/SKU/详情页/视频批量生成】。 # ── 核心用户与场景 ── 主要用户是【电商卖家与代运营】，他们在【单品上新要全套合规素材，人工出图慢且贵】的场景下使用，期望得到【痛点/卖点洞察 + 平台规格的全套内容素材】。 # ── 功能清单（MVP）── 1. 全网洞察：公开网页检索提炼痛点/卖点/创意方向（零密钥可用） 2. 图片创作：主图套装 / SKU 套图 / 详情页竖图，按平台规格 3. 视频工坊：文生视频三类规格 4. 合规与费用：违禁词初筛 + 报价确认后才扣费 + 成果管理 # ── 技术约束 ── - 技术栈：【React 18 + Vite 前端 + Express 单文件后端 + BOLI CLI（生图/生视频）】 - 全部本地运行，不依赖云服务；密钥走环境变量，代码里绝不硬编码 - 端口 【5173 Web / 8790 API】，启动方式：【npm install && npm run dev】 - 关键步骤有实时进度提示；失败要给可读的中文报错 # ── 质量要求 ── - 先给我目录结构和关键模块设计，我确认后再写代码 - 附 README（安装、启动、常见问题），按项目规范不硬编码任何密钥与内网地址 - 边界情况都要有兜底提示，宁可报错清晰也不静默失败
填空技巧「解决什么问题」越具体，AI 一次做对的概率越高。写「给人看报告」不如写「给新手照抄结构」。
小步快跑先让 MVP 跑通再迭代功能；一次让 AI 做十个小功能，不如三轮各做三个。
安全红线永远在提示词里写明「密钥走环境变量」——这是本系列所有项目的铁律。
验收标准把「先出设计再写码」「失败要中文报错」写进提示词，能有效防住糊弄式实现。
