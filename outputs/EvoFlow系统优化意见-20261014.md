# EvoFlow 系统优化意见（接入流程复盘 · 2026-10-14）

> 出处：1004 抖音视频拆解接入 EvoFlow 全流程复盘。
> 结论：**主要问题在项目脚本/技能包，已修复**（见 1004 新增 `scripts/install-into-evoflow.ps1` + `skills/evoflow-onboarding/SKILL.md`）。
> 本文件记录排查中发现的 **EvoFlow 平台侧** 3 个问题，供平台改进参考。

## 问题 1：`evoflow` CLI 在本机卡死（P0）

- **现象**：`evoflow --help`、`evoflow skills list`、`evoflow agents create` 全部超时卡死（前台后台均试过），必须 kill。
- **影响**：onboarding-kit 的 `hire-employee.js` 依赖 `evoflow agents create` / `employees hire`，被卡死拖累；`evoflow skills list` 无法用，技能状态只能靠 gateway HTTP API 确认。
- **建议**：
  1. CLI 启动加超时与失败快速降级（如 15s 未响应即提示「走 gateway API」）
  2. 排查 CLI 初始化是否在等待 gateway/DB 锁（怀疑与 gateway 同机互等）

## 问题 2：技能安装目录不一致（P1）

- **现象**：安装技能时有多个候选目录：`~/.evoflow/skills/custom`、`~/.evoflow/profiles/default/skills/custom`、`~/.evoflow-dev/skills/custom`。实测 **gateway 只从 `~/.evoflow/profiles/default/skills/custom` 加载**，写错目录「看起来装了、实际不生效」。
- **影响**：用户/AI 按直觉复制到 `.evoflow` 或 `.evoflow-dev`，技能列表里看不到；排查成本高。
- **建议**：官方文档明确「技能唯一生效目录 = profiles/default/skills/custom」，或 gateway 兼容多个候选目录并给出告警。

## 问题 3：扩展安装没有 UI 外通道 + 注册表位置与文档不符（P2）

- **现象**：
  1. 官方文档说扩展安装在 `~/.evoflow/ui-extensions/`，但实测注册表在 **`~/.evoflow-dev/ui-extensions/registry.json`**（文档写的是旧位置）。
  2. gateway openapi 里没有扩展管理 API（tags 无 extensions/ui-extensions），安装只能改 registry.json 或点面板 UI。
- **影响**：AI 无法通过 API 自动装扩展，教程里「让 AI 代办」的承诺打折。
- **建议**：文档更新注册表真实路径；openapi 增加 `POST /api/extensions`（注册 folder-link 扩展）以便 AI 全自动接入。

## 其他备注

- venv python（`D:\dev\github\EvoFlow\backend\.venv\Scripts\python.exe`）启动极慢/偶发挂起，疑似与残留进程堆积有关；清掉僵尸进程后恢复正常。建议平台侧给进程加看门狗，或文档注明「venv 调用前先清 python 残留进程」。
- gateway `/api/knowledge/{dataset_id}/sync-local` 与 owned Vault 知识库是两套体系：前者 dataset 为空（`{"items":[]}`），后者由 venv 服务管理。AI 侧 `knowledge` 工具走的是 owned Vault，与 gateway dataset 不互通，文档需澄清。
