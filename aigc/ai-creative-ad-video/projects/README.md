# 漫剧项目目录约定（唯一真相）

每个新片子：复制 `_TEMPLATE` 一份，重命名为 `<项目名>-<yyyymmdd>`。

```
projects\<项目名>-<yyyymmdd>\
├── 01-topic\        选题           ← 编剧写
├── 02-novel\        小说底本       ← 编剧写
├── 03-script\       剧本           ← 编剧写
├── 04-shots\        分镜表         ← 编剧写（已并入）
├── 05-meta\         风格宪法 + 指令单 + 预算   ← 导演写
├── 06-spec\         人物/道具/场景清单 + 生图prompt ← 导演写 / 生成师写
├── 07-assets\       三视图、四视图  ← 生成师写
├── 08-keyframes\    每镜首帧        ← 生成师写
├── 09-video\        draft\ final\  ← 生成师写
├── 10-audio\        voice\ sfx\ bgm ← 剪辑师写
├── 11-deliver\      成片 字幕 封面   ← 剪辑师写
└── _runs\           调用日志
```

## 流转（跨目录只许顺流读，谁都不改上游文件）

| 环节 | 岗位 | 读 | 写 |
|---|---|---|---|
| 1 | AIGC 编剧 `manju-writer` | 工具包指令文件 | `02-novel\` `03-script\` `04-shots\`（大纲/小说/剧本/分镜） |
| 3 | AIGC 导演 `manju-director` | `03-script\` + `04-shots\` | `05-meta\` `06-spec\*.json` |
| 4 | AIGC 生成师 `manju-generator` | `05-meta\shotlist.json` + `06-spec\` | `07-assets\` `08-keyframes\` `09-video\` |
| 5 | AIGC 剪辑师（⏸暂停） `manju-editor` | `09-video\final\` + `03-script\` + `04-shots\` | `10-audio\` `11-deliver\` |

## 三条不可破的规则

1. **`05-meta\shotlist.json` 是唯一执行依据**。生成师不自己编 prompt，画面不对就回去改 shotlist。
2. **文件名即对应关系**。`08-keyframes\S01-01.png`、`09-video\final\S01-01.mp4`、`04-shots\shots.md` 里的分镜 1，三处 `S01-01` 必须一致。重做一镜只换一个文件。
3. **资产与镜头分层**。`07-assets` 按角色/场景名索引，全片甚至全系列复用；`08-keyframes` 和 `09-video` 按 shot_id 索引，一镜一份。

## 生成参数（固定，不许改）

- 生视频：`seedance2.0_fast_vision`，分辨率只用 `480p` / `720p`（模型本身无 1080p），时长 4–15 秒
- 生图：`智能图片V2.5 Fast`，resolution 只用 `1K`，ratio 整数枚举 `2=16:9 / 3=9:16`
- 全片共用一个 seed，共用一份负面词（来自 `负面2.md`）
- 文字字幕只在 `11-deliver` 出现，不让视频模型生成中文

## 组织与负责人

部门：**AI漫剧**（5 个专业岗 + 1 个被动查资料岗）

```
                    用户（银泰）
                         │
                   AIGC 导演 manju-director   ← 部门负责人
                         │
     ┌──────────────────┼──────────────────┐
  AIGC 编剧              AIGC 生成师          AIGC 剪辑师
  manju-writer          manju-generator     manju-editor
 （大纲/小说/剧本/分镜）
```

**负责人是 `manju-director`（AIGC 导演）**，理由：全片唯一一个同时握有
「风格宪法 + 指令单 + 积分预算」三个全局变量的岗，只有他能判断某一镜要不要
返工、要不要换参考图。上下游都向他汇报。

`manju-kb-officer`（漫剧工具包知识官）不在这条线上，是被动查资料岗，不汇报、不派活。

## 模型分配

平台默认是 `deepseek-v4-flash`（**无视觉**）。注意：主模型不支持视觉时，`view_image`
不会报错，而是悄悄把图片转成文字摘要 —— 所以需要看图的岗位必须显式换模型。

| 岗位 | 模型 | view_image | 理由 |
|---|---|---|---|
| AIGC 生成师 | `doubao-seed-2.0-lite` | ✅ | 唯一能"看见"产出的岗，三视图/四视图必须真看图验收 |
| AIGC 导演 | `doubao-seed-2.0-lite` | ✅ | 负责人要抽查首帧与风格一致性，不能只听汇报 |
| AIGC 编剧 | 默认 `deepseek-v4-flash` | — | 纯文本创作 |
| AIGC 剪辑师（⏸暂停） | 默认 `deepseek-v4-flash` | — | ffmpeg 拼片，ffprobe 读元数据即可 |

生视频模型与生图模型在生成师内部写死（不是 agent 模型）：
`seedance2.0_fast_vision`（480p/720p，4–15s）、`智能图片V2.5 Fast`（1K）。

## 质检策略（只查最便宜、最影响一致性的两处）

1. **三视图出完立即查**：性别年龄、发型服装配饰、三视角比例统一、背景纯色
2. **四视图出完立即查**：光源方向与 style-lock 一致、无人物、四格无 180° 反向复制

首帧和视频不逐镜检查（图贵、量大），由导演抽查第一镜与最后一镜 + 风格一致性。
理由：**三视图歪了，后面所有镜头都会歪**，质检点放这里性价比最高。

## 自动交接规则（已配进各岗 soul）

平台机制：员工交工时填 `handlers`，只能派 **直属下级**；低风险立即唤醒，中风险等用户「同意派发」。

组织是星型，**导演中转**：

```
导演 ──派──> 编剧  ──交工回执──> 导演
导演 ──派──> 生成师 ──交工回执──> 导演
导演 ──派──> 剪辑师 ──交工回执──> 导演
```

| 岗位 | 交工时 handlers 指向 | read_outputs |
|---|---|---|
| 导演 | manju-writer（四件产物） | 05-meta/style-lock.md、01-calib/metric-ruler.md |
| 编剧 | manju-director | outline/novel/script/shots 四件 |
| 生成师 | manju-director | 09-video/final、_runs/video-runs.jsonl |
| 剪辑师 | manju-director | 11-deliver/final.mp4、final.srt |

**同级不能互派**（三岗均非直属），必须经导演中转。
要同级直连只能用「派发 / wake」通道，不走正式交工。

转交审批策略：导演设为 `approval_for_risky`（中风险以上要用户放行）。
生成师一开工就花积分，属于中风险，**必然停在用户确认这一步**。

## 第 0 步：题材调研与对齐（最先做，做完必须停下）

用户只给**题材词或剧名**，导演自己补全题材类型再去查，不反问用户。

### 0.1 先查库
读 `library/_index.md`：
- 有同题材且 90 天内更新 → 直接用，跳过联网
- 有但超 90 天 → 标记待复查，重查后更新
- 没有 → 联网查

### 0.2 出门查（web_search，至少 3 部对标）
```
① <题材> + 短剧/漫剧 + 爆款/排行/榜
② <题材> + 剧情/结构/套路/爽点
③ <题材> + 名场面/爽点/盘点
④ （女频/男频）<题材> + 大女主 | 重生 | 无金手指
```
必须扫同题材的**不同子型**（子型不同、爽点结构不同）。

### 0.3 七个维度（缺一项即不合格）
| # | 维度 | 要交什么 |
|---|---|---|
| 1 | 爆款开头 | 同赛道前 3 集怎么开局，第 1 个事件是什么 |
| 2 | 高潮 | 高点隔几集一次、落在什么位置 |
| 3 | 反转 | 类型、怎么埋、每集几次 |
| 4 | 爽点 | 类型、触发方式、密度 |
| 5 | 钩子 | 集尾怎么留、平路最长几集 |
| 6 | **共同点** | 这几部**都有的**做法 —— 这才是铁律 |
| 7 | 子型差异 | 同题材不同子型分开说 |

每条带出处剧名。**「感觉很燃」不算做完，必须落到数字。**

### 0.4 沉淀进资料库（跨项目持久积累）
写到 `library/genres/<题材>/`：
- `research.md` — 七维度报告
- `metric-ruler.md` — ★可数指标表
- `feature-library.md` — 招式库，每条标出处

并在 `library/_index.md` 记一行。

### 0.5 ★硬止点：停下等用户对齐
把报告摆给用户，问「这个题材的爆款结构我查到了，方向对不对？」

**没有得到明确回复，不许写 style-lock、不许派任何下游。**

## 题材资料库

```
library/
├── _index.md                    总索引：题材 → 目录 → 最后更新 → 用过的项目
└── genres/<题材>/
    ├── research.md
    ├── metric-ruler.md
    └── feature-library.md
```

**为什么建这个**：材料原话——「尺子只从当次拿到的那一两部标杆里长出来，用完就锁死，再没出过门」。
反过来，每次出门的结果不沉淀，就是反复掏同一份学费。查一次、沉淀一次、下次直接复用。

## 现有题材库的局限

`100个第一人称pov选题.txt` 只有 4 类共 100 条，**全是情感向**
（亲情 25 / 爱情 25 / 个人成长 25 / 友情 25）。

**不覆盖修仙、重生、星际等主流漫剧题材**，所以这些必须靠导演联网查，
查完沉淀到 `library/genres/` 自己积累。
