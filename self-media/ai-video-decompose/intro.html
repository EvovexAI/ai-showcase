01

项目定位

它是什么、不是什么，一句话说清边界。

这是拆解能力的全栈工程化版本：apps/api（Fastify + Prisma + SQLite）+ apps/web（Next.js 14），把「链接 → 下载 → 转写 → 关键帧 → 章节 → 分镜」做成正规流水线，数据落库、详情页可视化、三种格式一键导出。适合当工程化参考或二次开发底座。

#Next.js 全栈#分镜表#章节切分#可视化详情#monorepo

交付物

  • 拆解全流程 Web 应用（列表 + 详情页可视化）
  • 脚本 Markdown / 章节 JSON / 分镜 JSON 三种导出
  • Fastify API（apps/api 10 个模块）
  • 含样例数据的 dev.db
02

目标

06

日常怎么用

单开网页只是「手动挡」。接入 EvoFlow 后，同一个能力有四种发起方式，外加一条沉淀闭环。

工作台对话发起

在 EvoFlow 对话框直接 @员工 甩一条任务，员工调起本台技能，分镜与章节报告直接回进对话。

手机 IM 发起

员工接入飞书 / 钉钉 / 微信等渠道后，手机发消息即可发起——通勤路上顺手一发，拆一条链接就跑完了。

自动化定时发起

把「拆一条链接」挂成自动化任务：按计划自动执行，结果准时出现在对话和面板里。

EvoFlow 面板直看

本台 UI 以扩展面板嵌进 EvoFlow，不切窗口，对话和操作台同屏。

沉淀闭环：越用越聪明关键不在跑一次，而在产出落进知识库，反哺之后的每一次发起

发起对话 / IM / 自动化任一入口把任务丢给员工
执行员工调本台技能流水线跑完，产出分镜与章节报告
沉淀报告进知识库视频拆解库（建议命名）自动归档、可检索
复用员工查库再生成下次同类任务先查历史产出，结论更准
复用的结论又变成下一次发起的输入 —— 知识库越厚，建议越准
EvoFlow 接入本项目尚未注册 EvoFlow 资产——用 evoflow-onboarding-kit 一键接入：注册扩展面板 → 同步知识库 → 雇佣员工，四个脚本一条龙（已在拆解台 / 博主分析器打样）。

常见问题

为什么是「原型」？
链路与界面已跑通并带样例数据，但按系列标准（文档/稳定性/真实任务验证）还未达「可用」，用于体验与二开。
转写模型在哪配置？
见 apps/api 的 README，本地 Whisper 或云端二选一。
和 8765 拆解台重复吗？
定位不同：本台是 Next.js 工程化全栈版，8765 是 Python 轻量实战版。

想自己做一个？0→1 提示词

把下面整段喂给 AI 编程助手（ZCode / Cursor 等）。蓝色填空是你要替换的部分。

从 0 到 1 建项目提示词替换蓝色填空 → 整段复制 → 发给 AI
# ── 角色与目标 ── 你是资深全栈工程师。请帮我从零开发一个本地工具：【AI 视频拆解 Web 全栈应用——链接进，转写/关键帧/章节/分镜出，可视化详情页】。 # ── 核心用户与场景 ── 主要用户是【内容团队与全栈开发者】，他们在【要把视频拆解从脚本升级为可管理、可导出的工程化工具】的场景下使用，期望得到【结构化的分镜/章节产出 + 可视化拆解详情】。 # ── 功能清单（MVP）── 1. 输入：视频链接提交表单 + 任务列表管理 2. 流水线：下载 → 音频转写 → 关键帧抽取 → 章节切分 → 分镜生成 3. 详情页：转写稿、关键帧、章节、分镜可视化展示 4. 导出：脚本 Markdown / 章节 JSON / 分镜 JSON # ── 技术约束 ── - 技术栈：【Next.js 14 + React 18 + Fastify + Prisma/SQLite + pnpm monorepo(turbo)】 - 全部本地运行，不依赖云服务；密钥走环境变量，代码里绝不硬编码 - 端口 【3001 API / 3002 Web】，启动方式：【pnpm dev】 - 关键步骤有实时进度提示；失败要给可读的中文报错 # ── 质量要求 ── - 先给我目录结构和关键模块设计，我确认后再写代码 - 附 README（安装、启动、常见问题），按项目规范不硬编码任何密钥与内网地址 - 边界情况都要有兜底提示，宁可报错清晰也不静默失败
填空技巧「解决什么问题」越具体，AI 一次做对的概率越高。写「给人看报告」不如写「给新手照抄结构」。
小步快跑先让 MVP 跑通再迭代功能；一次让 AI 做十个小功能，不如三轮各做三个。
安全红线永远在提示词里写明「密钥走环境变量」——这是本系列所有项目的铁律。
验收标准把「先出设计再写码」「失败要中文报错」写进提示词，能有效防住糊弄式实现。
