## 用户操作流程

### 阶段 1️⃣：首页 - 视频输入与分析

**用户看到的界面：**

```
┌─────────────────────────────────────────┐
│ 🎬 AI Video Decompose                   │
│ 抖音视频一键分析 - 关键帧/口播脚本/章节结构 │
└─────────────────────────────────────────┘

【输入区域】
┌─────────────────────────────────────────┐
│ 视频输入                                  │
│                                          │
│ [粘贴链接/ID/路径...] [base▼] [🚀拆解] [🔄刷新]│
│                                          │
│ 💡 支持：抖音分享链接 / 视频ID / 本地.mp4  │
└─────────────────────────────────────────┘

【历史记录区域】
┌─────────────────────────────────────────┐
│ 📋 最近拆解 (还没有)                      │
│                                          │
│ 还没有拆解过视频                          │
│ 在上面输入视频链接开始拆解吧 →            │
└─────────────────────────────────────────┘
```

**用户操作步骤：**

1. 在输入框粘贴视频URL/ID/本地路径
2. 选择AI模型精度（tiny/base/small/medium）
3. 点击 🚀 一键拆解
4. 等待分析完成（后台调用Python脚本）
5. 新的分析结果自动出现在列表顶部

**系统发生的事情：**
- 调用 `/api/video-decompose/analyze`
- 后端执行Python分析脚本
- 生成报告JSON + 关键帧截图
- 数据存储到数据库
- 前端自动刷新历史列表

## 界面设计说明

### 信息架构

**首页 (http://localhost:3002/video-decompose)**
- 分为两个主要区域：
  1. **输入区域**（顶部）：视频输入 + 模型选择 + 操作按钮
  2. **历史列表**（下方）：过去的分析结果

**详情页 (http://localhost:3002/video-decompose/:id)**
- 分为多个区域：
  1. **头部**：返回按钮 + 标题 + 快速统计
  2. **快速操作**：三个导出按钮
  3. **标签页导航**：4个标签页切换
  4. **内容区域**：根据标签页显示对应内容

### 设计原则

✅ **符合用户行为习惯：**
- 从左到右：输入 → 等待 → 查看结果
- 从上到下：摘要信息 → 详细数据
- 从列表到详情：浏览 → 深入

✅ **视觉层级明确：**
- 标题用大字号 + 粗体
- 关键数据用颜色高亮（绿色成功、蓝色信息等）
- 操作按钮用明显的色块
- 可交互元素用悬停效果提示

✅ **信息密度适中：**
- 首页摘要：只显示最重要的统计数据
- 详情页：按标签页组织，避免信息过载
- 每个卡片：图文结合，易于扫描

## 产生的文档与数据

### 1. 📊 数据库记录

每次分析生成一条 `VideoDecomposition` 记录

### 2. 📄 可导出文档

#### 脚本文档 (Markdown)
路由: `GET /api/video-decompose/:id/export/script.md`
- 完整的口播脚本
- 语音分析数据
- 按段落拆解的脚本内容

#### 章节表 (JSON)
路由: `GET /api/video-decompose/:id/export/chapters.json`
- 所有章节的结构化数据
- 每个章节的时间、标题、摘要

#### 分镜表 (JSON)
路由: `GET /api/video-decompose/:id/export/scenes.json`
- 所有分镜的结构化数据
- 每个分镜的时间、视觉类型、语音文本

### 3. 🖼️ 关键帧截图

存储位置: `{projectPath}/analysis/scenes/`
- scene_001.jpg、scene_002.jpg 等
- 每个分镜的关键帧截图

## 系统架构

### 技术栈

```
Frontend (Next.js 14)
├── /video-decompose (列表页)
├── /video-decompose/[id] (详情页)
└── API调用 → http://localhost:3001

API Server (Fastify + Node.js)
├── POST /api/video-decompose/analyze
│   ├── 调用 Python 分析脚本
│   └── 存储结果到数据库
│
├── GET /api/video-decompose (列表)
├── GET /api/video-decompose/:id (详情)
│
└── 导出路由
    ├── GET /api/video-decompose/:id/export/script.md
    ├── GET /api/video-decompose/:id/export/chapters.json
    └── GET /api/video-decompose/:id/export/scenes.json

Database (Prisma + SQLite)
└── VideoDecomposition 表
```

### 数据流

```
用户输入视频链接
    ↓
调用 /api/video-decompose/analyze
    ↓
后端调用 Python 分析脚本
    ↓
生成报告 + 关键帧截图
    ↓
存储到数据库
    ↓
前端自动刷新列表
    ↓
用户看到新结果出现
    ↓
点击卡片进入详情页
    ↓
查看完整分析 + 下载文档
```

## ✨ 关键改进点

### 原来的问题
- ❌ 列表卡片不可点击，用户无法查看详细信息
- ❌ 没有详情页面
- ❌ 分析结果产生的所有数据都无法访问
- ❌ 用户不知道"拆解"之后发生了什么

### 现在的解决方案
- ✅ 列表卡片可点击，进入详情页
- ✅ 详情页用标签页组织4个主要视图（概览/脚本/章节/分镜）
- ✅ 提供3个可下载的文档（脚本Markdown/章节JSON/分镜JSON）
- ✅ 清晰的信息架构和视觉层级
- ✅ 每个步骤都有明确的用户反馈
