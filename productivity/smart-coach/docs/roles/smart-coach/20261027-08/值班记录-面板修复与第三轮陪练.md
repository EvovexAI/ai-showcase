## 一、面板 8769 空回复故障 → 已修复

**现象**：`GET /api/health` 在 TCP 握手成功后返回 `Empty reply from server`（curl exit 52），面板全站不可用。

**根因**：端口 8769 上有 3 个 `python scripts/web_server.py` 进程同时 LISTEN
（PID 35512 起于 09:58，另有 16:42 起的两份）。由于未设置 `allow_reuse_address`，
后启动的进程绑不上端口但仍挂着监听，先连上的那个（PID 35512，线程数=1、8MB，
属异常僵尸态）接受连接后不回应；新进程因为没真正绑上，日志里看不到请求。

**处置**：结束僵尸监听进程 35512，剩余正常进程即刻恢复响应。
`GET /api/health` → `{"ok": true, "service": "smart-coach", "port": 8769}`。

**待拍板（代码层，未擅自改）**：
1. `scripts/web_server.py` 的 `ThreadingHTTPServer` 建议开 `allow_reuse_address = True`，
   并在启动时检测端口占用、拒绝静默双开；
2. `PUT /api/progress` 对 `mastery` 是**浅覆盖**（`current.update(data)`），
   只传部分 mastery 会把其余节点抹掉 → 实测把 n1~n4 丢掉、percent 从 23 跌到 11。
   建议改成按 key 深合并。本轮已用全量 mastery 回写修正。
